# 编辑模块持有文本与撤销，平台调用集中隔离

状态：已接受模块责任和候选验证路线，依据第三轮 Q21 及用户“全部按建议”的确认；具体第三方依赖尚待原型验收。

首版采用自有 C 应用调用成熟编辑模块的方向，以 Win32、Scintilla 和 Lexilla 为候选验证路线。编辑模块持有文本缓冲、选区、光标与撤销；应用模块负责文档生命周期、标签和操作流程，不再长期维护另一套相同文本及撤销栈。这样可以复用成熟编辑能力，并避免两套文本状态的内存开销和同步复杂度；代价是编辑行为依赖所选模块，其搜索、撤销与大文件能力需要通过项目验收。

平台模块集中处理 Windows 窗口、文件对话框、文件系统与系统集成，可移植逻辑通过项目需要的少量 C 接口使用能力。适配器封装编辑模块的调用细节，不将整套窗口消息逐条换名转发；首版也不建设通用跨平台 GUI 框架。未来 Linux 可复用应用与编码逻辑，同时补充对应的平台适配，届时仍须验证实际接口是否满足移植需求。

编辑模块中的文本表示采用 UTF-8，文件原编码、BOM 和换行信息单独保留，编码模块执行严格转换。该选择不允许保存时自动改变文件编码、统一混合换行符或用替代字符掩盖转换失败。

## 采用条件

候选路线必须验证 C 调用、首批语言、中文输入和高 DPI、编码往返、大文件与长行、可取消搜索、撤销资源保护以及保存失败时的数据保留。未通过时报告证据并调整实现方案；更换候选模块不能自动取消已确认功能。具体标准见[首版需求规格](../../.scratch/editor-mvp/spec.md)。
