状态：需求已确认。用户在三轮访谈中分别回复“全部按建议”，确认 Q1～Q8、Q9～Q18 和 Q19～Q22。本文是首版需求基线；性能和兼容性尚未实测，具体依赖仍须通过原型验证。

整理日期：2026-09-30。

## 首版范围摘要

| 方向 | 已确认的要求 |
| --- | --- |
| 产品定位 | 文本、配置文件、代码阅读与轻量修改；Windows 10/11 x64 中文便携版 |
| 编辑与阅读 | 多标签、撤销/重做、语法高亮、当前行高亮、选中文本匹配高亮、行号、括号匹配、折叠、查找替换和正则 |
| 编码与显示 | 编码检测、按指定编码重新读取、显式转换保存编码、字体选择、浅色/深色、高 DPI、中文输入支持 |

## 用户已明确的目标

- 开发 Windows 桌面文本编辑软件，功能比系统 Notepad 丰富，整体保持轻量。
- 支持语法高亮、当前行高亮、选中文本匹配高亮，改善代码阅读体验。
- 支持编码检测，以及按指定编码查看文件。
- 支持字体选择。
- 重视性能和文件打开速度。
- 自有代码全部使用 C，允许通过 C 可调用接口使用内部由其他语言实现的第三方组件，采用模块化设计。
- 当前 UI 仅支持 Windows，将来可能支持 Linux；核心逻辑与平台调用分离，具体适配接口尚待设计。

## 用户明确不需要的功能

- 插件。
- 宏。
- 自动更新。
- 备份文件。
- 记住打开过的文件。

保存个人设置，不保存最近文件列表、会话、文档内容和光标历史；保留关闭时的未保存提示。不保留备份文件，允许安全保存期间短暂生成临时文件。首版不加入自动保存、崩溃恢复、插件、宏或自动更新。

## 第三轮已确认的决定

确认依据：用户第三次回复“全部按建议”，采用 Q19～Q22 的推荐项。技术路线确定了验证方向，不表示已经完成性能或兼容性验证。

### Q19：性能目标与测量条件

以当前开发机、本地磁盘上的固定样本作为初始参考环境，使用 Release x64 构建；启动耗时从新进程启动计起，包含必要的第三方库初始化，直到编辑区可输入。可重复的文件缓存已热测试每项至少 20 次，以 P95 对照下表的延迟目标，首次读取与冷缓存结果另外报告。磁盘介质、系统版本和构建版本随报告记录；网络文件等不同场景分别报告，环境干扰需记录，不能在观察结果后仅删除慢样本。

| 项目 | 已确认目标 | 说明 |
| --- | --- | --- |
| 新进程空窗口启动到可输入 | ≤ 500 毫秒 | 每次启动新进程；不以空白窗口出现就算完成 |
| 10 MB 普通文件完整载入到可编辑、可全文搜索 | ≤ 1 秒 | 常规多行样本，完整功能模式；着色可增量完成 |
| 100 MB 文件完整载入到可编辑、可全文搜索 | ≤ 3 秒 | 大文件模式；超长单行另设样本 |
| 常规输入反馈 | P95 ≤ 50 毫秒 | 覆盖小文件及已载入的 100 MB 文件；昂贵批量操作另测 |
| 空窗口稳定私有内存 | ≤ 80 MiB | 不包含调试器；测量进程私有提交内存 |
| 单个 100 MB UTF-8 文档稳定私有内存 | ≤ 500 MiB | 无编辑和撤销历史，不在执行搜索；加载、搜索、编辑的峰值内存另行报告 |

这些是已确认的产品目标，不是实测结果。若原型达不到目标，必须给出测量结果、瓶颈与取舍，再调整方案；不得将实现未达标默认为降低需求。

### Q20：支持上限、加载过程与撤销

- 首版打开单文件的支持上限为 256 MiB，以磁盘文件字节数判断；100 MB 仍是专项验收规模。超过上限时在完整载入前明确拒绝，并提示限制，不尝试把 GB 级文件全部读入内存。
- 对正在打开的文件显示进度并允许取消；在完整解码、载入完成前不允许编辑该文档，其他已打开标签保持可操作。取消不留下可误保存的半份文档。
- 已保存文档的正常保存不清空撤销历史；各文档的撤销历史相互独立，关闭或明确重新读取文档时结束旧历史。
- 首版不承诺按精确条数或字节预算自动裁剪最旧撤销记录，也不悄悄清空历史。超大编辑或资源不足时优先拒绝该操作并提示，保留当前内容；资源保护机制需要原型验证。
- 全部替换仍须作为一次可撤销操作。搜索或替换准备阶段若被取消，不能留下部分替换；计算期间文档变化时，旧结果不得直接覆盖新内容。

### Q21：候选技术路线与模块责任

- 以 Win32 原生 UI、Scintilla 编辑模块、Lexilla 语言分析模块作为原型验证路线；自有源码全部使用 C，第三方模块构建可使用 C++ 工具链。
- 应用模块负责文档和标签的生命周期、命令流程、编码选择与保存策略；编辑模块负责文本缓冲、选区、光标和撤销，不在应用模块再长期维护一整套相同文本及撤销栈。
- 平台模块集中处理窗口、文件对话框、文件系统和系统集成；编码等可移植逻辑通过 C 接口使用能力，不直接依赖 Win32 类型或窗口消息。
- 编辑模块对外提供本项目需要的少量操作，由适配器封装 Scintilla 细节；不把整套 Win32 或 Scintilla 消息逐条换名转发。跨平台暂通过清晰的接口和源码依赖约束准备，不编写完整的通用 GUI 框架。
- 编辑模块内采用 UTF-8 文本表示，保留 CRLF/LF/CR 换行信息；文件原编码及 BOM 作为文档信息单独维护。编码模块负责严格解码、编码及无法表示字符的错误，不通过静默替换字符完成转换。
- 原型必须验证：C 调用、首批语言、中文输入和高 DPI、混合换行符及编码往返、100 MB 与长行、撤销内存、可取消搜索、失败保存时的数据保留。正则若需独立库，仍需服从 C 自有代码与便携分发约束。
- 已确认候选路线和接口原则；通过验证后才锁定具体依赖及接口。不能因候选缺少某个接口，就静默撤销已经确认的功能。

### Q22：首版分发要求

- 提供离线可运行的 Windows 10/11 x64 便携压缩包，在标准用户权限下使用，不要求用户额外安装运行库。
- 压缩包体积暂以不超过 20 MB 为目标，包含运行所需依赖与许可说明，排除源码、测试数据和调试符号；源码和调试符号可以另行分发。
- 程序不主动访问互联网，不包含遥测、更新检查或外部在线服务；用户主动选择的网络文件路径属于文件访问，另行处理错误与超时。
- 构建方式和依赖版本必须能够复现；安装包、文件关联、自动更新和 Linux 发行物均不进入本次首版交付范围。

- 当前执行环境只读查询结果：Windows 11 Pro Education N，版本 10.0.26200 / Build 26200，Intel Core i5-14400，12.0 GiB 内存；系统盘介质尚未确认。

## 已核实的约束事实

- 编码检测通常包含统计和启发式判断，结果不保证唯一或正确；需求应区分检测结果与用户明确指定的编码。参考 [ICU 检测说明](https://unicode-org.github.io/icu/userguide/conversion/detection)。
- BOM 可以提供编码线索，但不是所有文本文件都包含 BOM；UTF-8 的 BOM 用于标识编码，不涉及字节序。参考 [Unicode BOM FAQ](https://www.unicode.org/faq/utf_bom.html)。
- Scintilla 自身使用 C++，但 Windows 上的 C 应用可以调用其接口。因此，自有代码使用 C 与所有依赖均为 C 是不同约束；该模块目前为已确认的验证候选，尚未通过本项目验收。参考 [Scintilla 项目说明](https://www.scintilla.org/)和[调用接口文档](https://www.scintilla.org/ScintillaDoc.html#DirectAccess)。
- Lexilla 提供可供 C 调用的接口和 C 示例，负责语法着色及折叠所需的语言分析，与 Scintilla 编辑控件职责分离；具体使用方式仍需验证。参考 [Scintilla 5 迁移指南](https://www.scintilla.org/Scintilla5Migration.html)及 [Lexilla 文档](https://www.scintilla.org/LexillaDoc.html)。
- Lexilla 官方源码支持调整分析器集合后重新生成构建文件，可作为裁剪发行构建的依据。参考 [Lexilla 官方仓库](https://github.com/ScintillaOrg/lexilla)。
