# 04: 按指定编码查看与显式格式转换

**What to build:** 用户可以按指定编码重新读取磁盘文件，也可以显式转换文档的保存编码、BOM 或换行符；两个操作具有不同且可理解的行为，并保护未保存修改。

**Blocked by:** 03：多编码文件读取与原格式保存。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 17、40、41、42、45、46、47；验收场景 A05、A06、A08；需求依据 Q5、Q9、Q13。

## 验收标准

- [ ] 按指定编码查看通过重新读取磁盘文件实现，不把当前内存文本重新编码来冒充查看操作。
- [ ] 有未保存修改时重新读取先要求处理修改，默认选择取消；保存后继续、明确放弃后继续和取消均有可验证结果，取消或保存失败保留当前文档。
- [ ] 成功重新读取后文本与所选编码一致，旧撤销/重做历史结束；读取或解码失败不丢失原内存内容。
- [ ] 编码转换、BOM 变化和统一换行符均由用户显式触发；普通保存继续保留当前文档约定的格式。
- [ ] 仅编码、BOM 或换行符变化也会在实际改变保存结果时形成未保存修改，供保存和关闭等流程识别；保存成功与失败时状态均正确。
- [ ] 显式统一换行符支持规定的 CRLF、LF、CR 形式；未触发该操作时，混合换行中的原有行分隔保持不变。
- [ ] 无法表示字符的目标编码不能成功写入，不静默替换字符；失败结果、内存文本、磁盘字节和未保存修改状态均可验证。

## 验证方式

应用层命令连接真实组件和磁盘文件，覆盖成功、默认取消、保存失败、读取失败与严格转换失败；使用实际 UI 检查操作名称、提示默认项和状态显示。

## 范围与衔接

本工单只依赖单文档流程与多编码能力。多标签关闭对格式修改状态的识别在 20 联合 02 验收。
