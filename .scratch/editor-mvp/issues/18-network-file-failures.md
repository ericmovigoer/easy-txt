# 18: 网络文件访问失败与超时处理

**What to build:** 用户主动打开或保存网络文件时，程序对读取错误、写入失败和超时给出明确结果，并保留尚未保存的编辑内容。

**Blocked by:** 05：只读文件与外部变更处理；09：可取消的文件加载。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 49、72；验收场景 A06、A12；需求依据 Q7、Q14、Q22。

## 验收标准

- [ ] 用户主动选择的网络文件路径沿用正常打开与保存流程；访问失败、不可达、权限拒绝和超时有可理解的提示。
- [ ] 网络加载期间继续遵守进度、取消、未完成文档不可编辑和其他标签可操作的规则；失败或取消不留下可误保存的半份文档。
- [ ] 网络保存遵守保存临时文件与目标替换策略；创建、写入、替换失败或超时不报告成功，不静默丢失内存内容和未保存修改。
- [ ] 网络文件的外部修改与删除冲突仍需用户处理，有本地未保存修改时不自动重新读取或覆盖。
- [ ] 记录超时处理的可观察行为和测试条件，通过平台边界控制错误与延迟，再以实际可用网络路径补充验证。
- [ ] 网络文件性能与本地磁盘目标分开报告；程序不借网络文件功能引入主动联网、遥测、更新检查或在线服务。

## 验证方式

应用层命令与平台故障控制验证确定性错误，实际网络环境验证访问、断连或超时场景；记录环境、操作、结果和未执行项，不能把模拟通过冒充真实网络验收。

## 范围与衔接

本工单只处理用户主动选择的网络文件。规范未给出统一超时数值，具体策略在实现验证后记录，不在工单中凭空设定产品承诺。
