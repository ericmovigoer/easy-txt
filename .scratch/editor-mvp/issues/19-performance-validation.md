# 19: 性能目标验证与瓶颈修复

**What to build:** 用户和维护者可以依据可复现的实际 Release 程序测量，判断启动、完整载入、输入反馈与内存是否达到规格目标；对未达标瓶颈提供证据并修复。

**Blocked by:** 15：大文件模式；16：拖放、命令行与单实例打开；17：用户偏好持久化；18：网络文件访问失败与超时处理。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 53、70；验收场景 A11；需求依据 Q19。

## 验收标准

- [ ] 采用实际 Release x64 程序和当前开发机本地磁盘固定样本，重新核对并记录系统版本、硬件、磁盘介质、构建版本与候选依赖版本，不把历史参考机记录当成当前测量。
- [ ] 新进程空窗口从进程启动到编辑区可输入 P95 ≤ 500 毫秒，计入必要第三方库初始化。
- [ ] 10 MB 常规多行文件在完整功能模式下完整载入 P95 ≤ 1 秒；100 MB 文件在大文件模式下完整载入 P95 ≤ 3 秒，超长单行另设样本。
- [ ] 小文件和已载入的 100 MB 文件常规输入反馈 P95 ≤ 50 毫秒；昂贵批量操作另测并报告。
- [ ] 空窗口稳定私有提交内存 ≤ 80 MiB；单个 100 MB UTF-8 文档在无编辑、无撤销历史且未搜索时稳定私有提交内存 ≤ 500 MiB；测量不含调试器。
- [ ] 可重复的文件缓存已热测试每项至少 20 次，保留全部原始分布并以 P95 对照延迟目标；首次读取、冷缓存单独报告，新进程启动不等同于文件冷缓存。
- [ ] 固定样本目录、内容、精确字节大小和编码，涵盖常规代码、多行日志、长行与单行 JSON；MB 使用十进制字节，MiB/KiB 使用二进制单位。
- [ ] 分别记录首屏显示、完整载入可编辑和全部可搜索的时点，不以首屏代替完成；另报加载、搜索、编辑阶段峰值及稳定内存。
- [ ] 记录环境干扰，不在看到结果后只删除慢样本；网络文件单独报告，本机性能不能代替 Windows 10/11 兼容性验收。
- [ ] 对未达标项提供原始测量、瓶颈和修复后的复验；若需要改变已确认要求，保留未通过状态并凭证据单独讨论，不默认降低目标。

## 验证方式

使用实际 Release 程序和外部测量，交付可重复执行的测量方法、固定样本说明、原始数据、统计结果与瓶颈修复证据。性能测试与功能测试分工，不以单次观察代替分布。

## 范围与衔接

本工单沿用已确认的量化目标，触发阈值可调整不代表性能目标可降低。最终运行包若改变构建或依赖，应在 20 复验受影响指标。
