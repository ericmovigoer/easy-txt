# 02: 多标签与关闭流程

**What to build:** 用户可以同时编辑多个相互独立的文档，重复打开文件时回到已有标签，并在关闭标签或退出时逐个处理未保存修改。

**Blocked by:** 01：UTF-8 单文档编辑闭环。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 6、8、9、10、11、12、15、16、17；验收场景 A01、A08；需求依据 Q4、Q9、Q18。

## 验收标准

- [ ] 每份文档有独立标签，多个未命名文档互不影响；文本、光标、选区和撤销/重做状态随文档保留，切换标签不会串用内容或历史。
- [ ] 重复打开同一文件时定位到原标签，不产生第二份编辑状态；通过能指向同一文件的不同路径表示验证文件识别行为。
- [ ] Ctrl+Tab 切换标签，Ctrl+W 关闭当前标签，菜单中的同类操作结果一致。
- [ ] 关闭有未保存修改的文档时提供保存、放弃和取消；保存失败或取消保存时保留文档与内容。
- [ ] 批量关闭或退出按顺序处理未保存修改；用户取消后停止后续关闭，已完成的关闭无需恢复，尚未处理的标签保留。
- [ ] 正常保存后仍能撤销保存前的编辑；关闭文档后旧历史结束，重新打开不继承已关闭文档的撤销记录。
- [ ] 关闭决策使用文档公开的未保存修改状态；后续编码、BOM 和换行符变化可接入同一状态，避免仅通过可见文字变化判断。
- [ ] 退出后不恢复标签或编辑状态，也不持久化文档路径、内容或文件历史。

## 验证方式

以应用层命令验证文档隔离、重复打开和关闭决策；用真实 Windows UI 验证标签、快捷键与提示。检查各分支中的文本、未保存修改和可用撤销/重做行为。
