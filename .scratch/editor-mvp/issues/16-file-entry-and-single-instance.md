# 16: 拖放、命令行与单实例打开

**What to build:** 用户可以拖放文件或从命令行传入多个路径；同一用户会话内再次启动程序会复用已有窗口，按传入顺序打开标签并定位已打开文件。

**Blocked by:** 02：多标签与关闭流程；09：可取消的文件加载。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 4、5、7、8；验收场景 A01；需求依据 Q4、Q18。

## 验收标准

- [ ] 从实际 Windows 文件管理器拖放一个或多个文件可以进入统一打开流程，保留加载进度、取消和失败提示。
- [ ] 命令行支持一次传入多个文件路径，含空格或中文等字符的路径被正确接收，不拆错参数。
- [ ] 同一用户会话再次启动时复用已有窗口，不创建第二份相互独立的同会话文档集合。
- [ ] 多个传入文件按传入顺序处理并呈现标签；重复打开同一文件定位原标签，原有文本、未保存修改和撤销历史保留。
- [ ] 某个路径读取失败、被取消或超过容量上限时结果明确，不产生半份文档，也不破坏已经打开的其他文档。
- [ ] 以真实的第二进程及实际拖放验证系统集成，不仅调用内部打开命令模拟成功。

## 验证方式

应用层命令验证路径顺序、重复文件和失败状态；真实 Windows UI、命令行启动和第二进程验证拖放及同会话复用。记录实际操作与结果。

## 范围与衔接

单实例行为限定同一用户会话；不新增文件关联、安装包或跨用户会话共享文档功能。
