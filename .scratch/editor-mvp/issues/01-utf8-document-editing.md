# 01: UTF-8 单文档编辑闭环

**What to build:** 用户可以启动中文 Windows 程序，新建或打开一份 UTF-8 文档，编辑并多步撤销/重做，再通过保存或另存为写回文件；保存失败时仍能保留并继续处理内存中的内容。

**Blocked by:** 无（可立即开始）。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 1、3、14、16、43、44、48、49、52、74、75、76、77、78；验收场景 A01、A05、A06、A08；需求依据 Q3、Q8、Q9、Q13、Q14、Q21。

## 验收标准

- [ ] 提供可构建、可运行的 Windows x64 中文程序，具备菜单栏、当前文档标签、编辑区和状态栏；通过 UI 完成新建、打开、编辑、保存、另存为的完整流程。
- [ ] 新建文档默认 UTF-8 无 BOM、CRLF；打开 UTF-8 有/无 BOM 的固定样本后普通保存保留 BOM 和各行 CRLF/LF/CR，不隐式统一换行符。
- [ ] 基本输入、多步撤销和重做可用；文本变化产生可观察的未保存修改状态，成功保存更新保存状态但保留撤销历史。
- [ ] 保存先在目标目录生成保存临时文件，写入成功后再替换目标；成功保存不遗留常驻备份文件。
- [ ] 通过平台边界分别控制读取失败、保存临时文件创建或写入失败、目标替换失败；错误明确可见，内存文本与未保存修改保留，未完成的保存不标成功，不直接截断原文件。
- [ ] 应用层公开文档命令连接真实编辑与编码组件，并以文本、状态、操作结果和磁盘字节验证上述行为；正常文件流程使用临时目录和真实文件系统。
- [ ] 遵循 ADR-0001、ADR-0002：自有源码使用 C，编辑模块持有 UTF-8 文本、选区、光标和撤销；应用模块不长期复制整套文本与撤销栈，可移植逻辑不依赖 Win32 类型或窗口消息。
- [ ] 记录候选组件版本、C 调用验证结果、构建步骤和当前限制；只建立本项目需要的少量适配操作，不在未满足采用条件时把候选依赖宣布为最终方案。

## 验证方式

应用层文档命令与真实组件集成测试为主，必要时由测试宿主提供 Windows 消息循环；用实际程序演示完整流程。测试断言用户可观察行为，不依赖私有函数、窗口消息序列或撤销栈内部布局。
