# 13: 超大编辑与资源不足保护

**What to build:** 用户执行输入、粘贴或批量替换时，如果操作规模或资源不足会危及文档，程序优先拒绝操作并提示，同时保留当前文本和可用的撤销/重做历史。

**Blocked by:** 02：多标签与关闭流程；06：基础编辑与定位操作；12：替换与可撤销的全部替换。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 15、34、60；验收场景 A08；需求依据 Q9、Q20。

## 验收标准

- [ ] 为输入、粘贴和批量替换验证可操作的资源保护机制，在超大操作或资源不足时优先拒绝并给出明确提示。
- [ ] 拒绝或失败后当前文本、选区相关可观察状态、撤销/重做行为和未保存修改均保持一致，不留下半次修改。
- [ ] 不得静默清空撤销历史，也不得把清空全部撤销缓冲描述为裁剪最旧记录；不承诺按精确条数或字节预算裁剪历史。
- [ ] 多个文档之间仍保持独立撤销历史，对一个文档的拒绝或失败不能清空其他文档的历史。
- [ ] 正常保存仍保留历史，成功全部替换仍一次撤销；对失败前后的撤销与重做执行实际操作验证，而非只检查标志。
- [ ] 使用真实编辑组件、压力样本与受控资源失败验证保护；报告候选组件的约束、实际可保护范围、内存观察与未通过项。
- [ ] 资源不足时优先保留当前内容，未达到保护要求时记录证据并调整方案，不能把破坏历史作为默认降级。

## 验证方式

通过应用层命令触发实际编辑与替换，结合受控资源失败和原型压力验证；逐步核对文本、撤销/重做、未保存修改以及各文档隔离。失败控制不另造一套文档操作接口。

## 范围与衔接

本工单使用受支持规模的压力样本，不新增 GB 级文件支持。稳定内存与阶段峰值的统一统计在 19 执行。
