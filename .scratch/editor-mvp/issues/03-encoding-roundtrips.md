# 03: 多编码文件读取与原格式保存

**What to build:** 用户可以打开各类规定编码的文件，看到当前编码及推测状态，在无法可靠解码时选择编码，并按原有编码、BOM 和逐行换行符保存。

**Blocked by:** 01：UTF-8 单文档编辑闭环。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 38、39、44、46；验收场景 A05；需求依据 Q5、Q13。

## 验收标准

- [ ] 支持 UTF-8 有/无 BOM、UTF-16 LE/BE、GB18030、GBK、Big5、Windows-1252；每种编码都有含适用字符的固定磁盘字节样本。
- [ ] 编码检测优先使用 BOM 和严格 UTF-8 校验；其他结果明确标为推测，无法可靠解码时提示用户选择，不用替代字符掩盖读取错误。
- [ ] 用户选择编码后能严格解码并看到文档，状态栏显示当前编码及适用的推测状态；取消选择不产生可误保存的乱码文档。
- [ ] 编辑模块内使用 UTF-8，原文件编码和 BOM 作为文档信息维护；普通保存保持识别或指定编码、BOM 及各行 CRLF/LF/CR。
- [ ] 对每种编码验证读取、修改、保存和重新打开；未改动样本的往返结果按预期磁盘字节核对，混合换行不被自动统一。
- [ ] 目标编码无法表示文档字符时阻止保存并明确提示；原文件不被错误覆盖，内存文本与未保存修改状态保留，不静默替换或丢字。
- [ ] 记录实际编码实现、候选依赖版本、固定样本和严格转换结果，为最终采用条件提供可复现证据。

## 验证方式

应用层打开、编辑和保存命令贯通真实编辑与编码实现，正常读写使用真实文件；自动化核对字节、文本与失败结果，编码状态栏用实际程序验证。

## 范围与衔接

本工单包含读取失败后的编码选择。对已打开文档按指定编码重新读取，以及显式改变保存格式，由 04 交付。
