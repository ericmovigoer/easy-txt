# 09: 可取消的文件加载

**What to build:** 用户打开文件时可以查看加载进度并取消，同时继续操作其他已打开文档；只有完整载入的文档才可编辑，超出支持上限的文件会提前被拒绝。

**Blocked by:** 02：多标签与关闭流程；03：多编码文件读取与原格式保存。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 56、57、58、59；验收场景 A07；需求依据 Q2、Q15、Q20。

## 验收标准

- [ ] 以磁盘文件字节数判断支持上限；超过 256 MiB 的文件在完整载入前明确拒绝并提示限制，不先把 GB 级文件全部读入内存。
- [ ] 覆盖上限以下、恰好 256 MiB 和超过上限的样本，不能因为上限判断而拒绝恰好达到上限的受支持文件。
- [ ] 打开期间显示可理解的加载进度并提供取消入口；读取、解码和载入过程的取消与失败均有明确结果。
- [ ] 未完整解码和载入的文档不可编辑或误保存；其他已打开标签在加载过程中仍可操作。
- [ ] 取消后不留下可误保存的半份文档，不破坏其他文档的文本、撤销历史或未保存修改；随后仍可重新打开文件。
- [ ] 完整载入的完成状态表示全部文本已可编辑且可供全文搜索，不以首屏显示或窗口出现冒充完成；着色允许增量完成。
- [ ] 在 UTF-8 和至少一种多字节或 UTF-16 编码上验证取消、失败与完成状态，使用 100 MB 和长行样本验证实际程序响应。

## 验证方式

应用层命令与受控平台读取失败验证状态及文档保护，真实文件验证加载；实际程序验证进度、取消、标签可操作性与完成时点。性能目标的完整统计由 19 执行。

## 范围与衔接

本工单交付加载行为和容量限制；减少显示增强功能的大文件模式由 15 交付。暂时没有查找 UI 时，完成状态仍须基于全部文本可用性验证。
