# 12: 替换与可撤销的全部替换

**What to build:** 用户可以按普通文本或正则条件替换当前文档或选区内的匹配，全部替换形成一次可撤销操作，取消准备或文档变化不会留下部分替换。

**Blocked by:** 11：正则查找与语法帮助。

**Status:** ready-for-agent

**需求追踪：** 轻量文本编辑器首版规格；用户故事 31、34、36、37；验收场景 A04、A08；需求依据 Q11、Q20。

## 验收标准

- [ ] 普通文本与正则模式均可替换指定匹配或全部匹配，文档/选区范围及大小写、整词选项与查找保持一致。
- [ ] 全部替换完成后一次撤销可恢复替换前的全部文本，一次重做可恢复该批替换结果；未保存修改状态与实际内容一致。
- [ ] 替换准备阶段耗时可取消，期间保持输入响应；取消后无部分替换、无虚假的成功结果或内容修改。
- [ ] 准备期间文档发生编辑时，不将旧计算结果直接提交到新内容；保留新编辑并给出可理解的结果或重新计算流程。
- [ ] 覆盖无匹配、零长度匹配、多字节字符和限定选区样本，验证不会无限循环、越过范围或产生损坏字符。
- [ ] 通过真实组件验证准备、取消、提交和撤销行为，记录调用约束与结果；不通过清空撤销历史来满足一次撤销要求。
- [ ] 正则替换语法在帮助中与实际行为一致，用户可理解替换文本中的特殊写法。

## 验证方式

以应用层命令核对替换前后文本、单次撤销/重做与未保存修改，控制准备阶段取消和并发编辑；实际 UI 验证长任务响应及提示。资源不足的拒绝路径由 13 进一步验证。

## 范围与衔接

范围限于当前文档及其选区。替换调度与结果提交必须以行为证明满足要求，不能用候选组件限制降低产品要求。
