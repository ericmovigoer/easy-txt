# 轻量文本编辑器首版规格

Status: ready-for-agent

整理日期：2026-09-30。

需求来源：输入规格记载的初始目标与三轮已确认决定 Q1～Q22。本次按标准规格结构整理；用户另行确认了本文的测试边界。候选依赖、性能目标和验收场景尚未经过应用实测。ready-for-agent 表示规格可交给 agent 开展验证与实现，不表示应用已经实现或验收通过。

## 问题陈述

用户需要在 Windows 上阅读和轻量修改文本、配置文件与代码。系统 Notepad 的阅读辅助和编辑能力不足，而用户希望软件保持轻量、打开文件迅速，不引入插件、宏或项目级开发环境的复杂度。

日常文件可能使用不同编码、BOM 和换行符。用户需要辨别编码、按指定编码查看以及显式进行编码转换，同时避免乱码、静默丢字和无意改变文件格式。面对大文件、长行、未保存修改、外部文件变化或保存失败时，软件必须给出可理解的状态并保留用户内容。

用户还需要中文界面、可靠的中文输入、可调字体和可离线运行的便携分发。软件可以记住用户偏好，但不记录文件历史、不恢复会话，也不保留文档内容或备份文件。

## 解决方案

交付 Windows 10/11 x64 中文便携文本编辑器，以多标签组织文档，提供基础编辑、多步撤销与重做、语法高亮、当前行高亮、选中文本匹配高亮、行号、括号匹配、折叠及当前文档查找与替换。

通过明确区分编码检测、按指定编码查看和编码转换，保留文档原有编码、BOM 及各行换行符；使用保存临时文件完成安全保存，并处理未保存修改、只读、外部变更和失败结果。10 MB 以内普通文件是完整体验重点，100 MB 文件必须专项验收；大文件或长行通过可见的大文件模式减少显示增强功能，单文件支持上限为 256 MiB。

自有代码全部使用 C，应用、编辑、编码和平台模块分工明确。以 Win32、Scintilla、Lexilla 为候选验证路线；先验证功能、性能和分发约束，再固定依赖版本及接口。首版只交付 Windows UI，同时保持可移植逻辑与平台调用隔离。

## 实现决策

### 产品与分发边界（Q1、Q7、Q22）

- 首版面向文本、配置文件、代码阅读与轻量修改；目标平台为 Windows 10/11 x64，界面为中文。
- 提供可在标准用户权限下离线运行的便携压缩包，不要求额外安装运行库。运行所需依赖和许可说明包含在包内；源码、测试数据和调试符号不计入运行包，可另行分发源码与调试符号。
- 压缩包体积暂以不超过 20 MB 为目标；构建方式和依赖版本必须可复现。
- 程序不主动访问互联网，无遥测、更新检查或外部在线服务。用户主动选择的网络文件路径属于文件访问，需处理错误和超时，并单独报告相关性能。

### 模块责任与候选路线（Q3、Q8、Q21）

- 遵循 ADR-0001：自有源码全部使用 C，允许依赖内部由其他语言实现、可由 C 调用的第三方组件；第三方模块构建可使用 C++ 工具链。
- 遵循 ADR-0002：Win32 原生 UI、Scintilla 编辑模块、Lexilla 语言分析模块是候选原型路线，尚未锁定最终依赖或版本。
- 应用模块负责文档与标签生命周期、命令流程、编码选择、保存策略和未保存修改状态；编辑模块持有文本缓冲、选区、光标和撤销。应用模块不得长期维护另一套相同文本与撤销栈。
- 平台模块集中处理窗口、文件对话框、文件系统与系统集成。平台边界需考虑文件、剪贴板、输入法和字体；编码等可移植逻辑通过 C 接口使用能力，不依赖 Win32 类型或窗口消息。
- 编辑适配器仅暴露本项目需要的少量操作，封装 Scintilla 细节；不得把整套 Win32 或 Scintilla 消息逐条换名转发，也不建设完整通用 GUI 框架。
- 编辑模块内使用 UTF-8 文本表示，保留 CRLF/LF/CR 换行信息；原文件编码及 BOM 作为文档信息维护。编码模块负责严格解码、编码和无法表示字符的错误。
- 具体接口、构建参数、依赖版本和异常实现细节在验证后确定。若正则需要独立库，仍须符合 C 自有代码与便携分发约束。

### 文档、标签与实例行为（Q4、Q9、Q18）

- 支持新建、打开、保存、另存为、拖放打开以及命令行传入多个文件路径。
- 同一用户会话下再次启动时复用已有窗口，按传入顺序打开标签；同一文件已打开时定位到原标签。新建未命名文档各自独立。
- 支持 Ctrl+Tab 切换、Ctrl+W 关闭。批量关闭和退出时逐个处理未保存修改，用户取消后停止后续关闭，不要求恢复此前已完成的关闭。
- 文档的未保存修改包含文本变化，以及会改变保存结果的编码、BOM 或换行符变化。退出后不恢复标签或编辑状态。

### 编辑、撤销与资源保护（Q9、Q20）

- 支持剪切、复制、粘贴、全选、多步撤销与重做、跳转行和整行增减缩进；自动缩进延续上一行。
- 默认 Tab 宽度为 4，Tab 键插入空格；允许改用制表符。自动换行默认关闭。
- 各文档撤销历史相互独立；已保存文档的正常保存不清空历史，关闭或明确重新读取时结束旧历史。
- 首版不承诺按精确条数或字节预算自动裁剪最旧撤销记录，不得静默清空历史。超大编辑或资源不足时优先拒绝该操作并提示，保留当前内容；资源保护机制必须原型验证。
- 全部替换作为一次可撤销操作。验证资源保护时同时检查文本、撤销/重做和未保存修改状态，不能把清空整个撤销缓冲视为裁剪最旧历史。

### 代码阅读与显示（Q10、Q12、Q16）

- 首批语言覆盖 C/C++、Python、JavaScript/TypeScript、JSON、INI、YAML、Markdown、HTML/XML、CSS、PowerShell/批处理。按扩展名选择语言，允许手动覆盖；未知类型按纯文本显示。
- 提供语法高亮、当前行高亮、行号、括号匹配和语言允许的折叠；折叠默认展开。
- 选中文本匹配高亮只对当前文档进行区分大小写的字面子串匹配，不要求整词。选区须为非纯空白的单行文本，允许单字符；取消选区即清除，选区稳定约 150 毫秒后更新。
- 选中文本匹配高亮与查找结果采用可区分的样式；在大文件模式中的默认开关遵循该模式规则。
- UI 由菜单栏、标签栏、编辑区和状态栏组成。提供浅色/深色主题，默认浅色；默认等宽字体，可选择字体、字号与缩放。
- 中文输入法、中文与英文混排、非 BMP 字符、字体回退、高 DPI 和常用操作键盘可达性必须验收。

### 查找与替换（Q11、Q20）

- 范围限于当前文档，可进一步限定选区。支持普通文本、大小写、整词、正则、上一个、下一个和全部替换；无效正则明确提示。
- 搜索不得长时间阻塞输入，耗时任务可取消。正则语法在选定组件后写入帮助。
- 搜索或替换准备阶段被取消时不得留下部分替换；计算期间文档发生变化时，旧结果不得直接覆盖新内容。
- 取消机制、计算调度和结果提交方式须通过原型验证；不能因为候选组件缺少直接接口而取消这些要求。

### 编码与换行符（Q5、Q13）

- 支持 UTF-8（有/无 BOM）、UTF-16 LE/BE、GB18030、GBK、Big5、Windows-1252。
- 编码检测优先考虑 BOM 和严格 UTF-8 校验，其他结果标为推测；无法可靠解码时提示用户选择。状态栏显示当前编码。
- 按指定编码查看通过重新读取磁盘文件完成，不等同于编码转换。有未保存修改时必须先处理修改，默认取消重新读取。
- 新建文件默认 UTF-8 无 BOM、CRLF。已打开文件普通保存保持识别或指定的编码、BOM 和各行原有换行符；编码转换及统一换行符均须显式操作。
- 严格处理解码与编码错误。目标编码无法表示字符时阻止保存并提示，不静默替换字符。

### 保存与外部变更（Q14）

- 保存允许在目标目录生成短暂保存临时文件，写入成功后替换目标，避免直接截断原文件；不保留备份文件。
- 失败时保留内存中的编辑内容并明确报告结果，不把未完成的保存标为成功。只读文件允许查看和另存为。
- 文件被外部修改或删除时提示；存在本地未保存修改时不自动重新读取或覆盖。
- 保存临时文件只属于保存过程，不构成备份、自动保存或崩溃恢复功能。文件系统失败和网络路径错误不能导致静默丢失编辑内容。

### 大文件模式与加载（Q2、Q15、Q20）

- 10 MB 以内普通文件是完整编辑体验重点；100 MB 文件及超长单行必须专项验收。暂定文件达到 20 MB 或单行达到 256 KiB 时启用可见的大文件模式，阈值可在原型实测后调整并记录依据。
- 大文件模式保留基础编辑、撤销、查找与替换、手动编码选择，默认关闭语法高亮、折叠、自动换行和选中文本匹配高亮；允许用户尝试逐项恢复显示功能。
- 单文件打开支持上限为 256 MiB，以磁盘文件字节数判断；超过上限须在完整载入前明确拒绝并提示限制，不把 GB 级文件全部读入内存。
- 打开过程中显示进度、允许取消。在完整解码和载入之前不得编辑该文档，其他已打开标签保持可操作。取消不留下可误保存的半份文档。
- 完整载入是文档已可编辑且可全文搜索；首屏出现或窗口出现不算完成。着色可以增量完成。

### 用户偏好与持久化（Q6、Q17）

- 在程序目录的配置文件中保存字体、字号、主题、窗口大小、Tab 宽度及缩进选项等用户偏好。
- 程序目录不可写时明确提示，本次运行的设置仍有效，不自动改写其他位置。
- 配置损坏时提示并采用默认设置，不静默覆盖损坏文件。
- 不保存文件历史、会话、文档路径、文档内容、搜索历史或光标历史；保留关闭时的未保存修改提示。

## 测试决策

### 测试边界与现有基础

用户已在本次对话中确认：主要通过应用层文档命令验证编辑、编码、搜索和保存行为，连接真实编辑与编码组件；文件失败通过平台边界模拟；中文输入法、高 DPI、窗口交互和性能用实际 Windows 程序验收。

- 仓库当前只有需求、领域词汇和 ADR，没有应用实现、构建脚本或现成测试。因此没有可复用的测试用例或已实现测试入口；以下入口是拟建边界，不能描述为现有能力。
- 以应用层公开文档命令作为主要自动化测试入口，驱动新建、打开、修改、选择、搜索、替换、撤销、重新读取、保存与关闭流程。通过文档文本、可观察状态、返回结果和磁盘字节判断行为；接口的精确签名留待原型确定。
- 测试贯通应用、编辑与编码模块，使用真实编辑适配器与真实编码实现；需要 Windows 消息循环时在测试宿主中提供，不将候选编辑控件假定为完全脱离平台运行。
- 正常文件读写使用临时目录和真实文件系统。不可写、读取失败、保存临时文件写入失败、目标替换失败及外部变更冲突等确定性异常，通过已规划的平台职责边界提供受控失败或事件；这是主要测试入口的依赖控制，不另建一套文档操作接口。
- Windows 原生 UI 验收通过真实程序观察菜单、标签、快捷键、字体、主题、输入法、DPI、拖放、单实例和命令行行为；性能验收也使用实际 Release 程序。两者补充应用层入口无法充分覆盖的系统集成行为。
- 好测试验证用户可观察的行为和错误结果，不依赖内部结构、私有函数、窗口消息调用次数、Scintilla 消息序列或撤销栈内部布局。允许内部实现重构而不改变验收期望。

### 性能目标与测量条件（Q19）

以下是已确认的产品目标，不是实测结果。以当前开发机、本地磁盘固定样本和 Release x64 构建作为初始参考环境；记录磁盘介质、系统版本与构建版本。MB 表示十进制文件字节数，MiB/KiB 表示二进制内存或长度单位。

| 项目 | 目标 | 条件与完成时点 |
| --- | --- | --- |
| 新进程空窗口启动到可输入 | P95 ≤ 500 毫秒 | 每次启动新进程，从进程启动计时，包含必要第三方库初始化，直到编辑区可输入 |
| 10 MB 普通文件完整载入 | P95 ≤ 1 秒 | 常规多行样本，完整功能模式；完整解码并可编辑、可全文搜索；着色可增量完成 |
| 100 MB 文件完整载入 | P95 ≤ 3 秒 | 大文件模式，直到可编辑、可全文搜索；超长单行另设样本 |
| 常规输入反馈 | P95 ≤ 50 毫秒 | 覆盖小文件和已载入的 100 MB 文件；昂贵批量操作另测 |
| 空窗口稳定私有内存 | ≤ 80 MiB | 不含调试器，测量进程私有提交内存 |
| 单个 100 MB UTF-8 文档稳定私有内存 | ≤ 500 MiB | 无编辑和撤销历史，未执行搜索；加载、搜索和编辑峰值另行报告 |

- 可重复的文件缓存已热测试每项至少 20 次，以 P95 对照延迟目标。首次读取和冷缓存结果另行报告；新进程启动不等同于文件冷缓存。
- 固定测试目录、样本内容、精确字节大小和编码；样本包含常规代码、多行日志、长行和单行 JSON，保留重复测量的原始分布。
- 分别记录首屏显示、完整载入可编辑、全部可搜索的时点，不以窗口或首屏出现代替完整载入。
- 记录环境干扰，不能在看到结果后仅删除慢样本；网络文件等不同场景单独报告。内存报告区分稳定值和阶段峰值。
- 本地参考机的测量不能代替 Windows 10/11 兼容性验收。若原型不达标，报告测量结果、瓶颈和取舍，再讨论方案调整，不得把未达标默认为降低需求。
